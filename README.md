## What a report looks like

Each report answers the questions the store page doesn't:

- **Ola 7.6.2** — analyzed without ever running the app: 32,228 classes, 13
  native libraries, every claim tagged observed / inferred / unknown.
  [report](apps/ola/report/)
- **YourHour 4.5.6** — a screen-time tracker that also ships a remote
  parental-control platform pairing the phone to an Android TV app.
  [report](apps/yourhour/report/)
- **Google Files** — a file manager with an "Ask Gemini" PDF Q&A sheet wired
  into the preview UI. [report](apps/google-files/report/)

Every report names the artifact it was built from: package or binary,
version, SHA-256, date, tools.

## Let an AI do the autopsy

Paste this into your AI agent, replace the two placeholders, done. It reads
only the few files it needs — not the whole repo:

```text
You are writing a teardown report for apps-autopsy
(https://github.com/mitunmanav/apps-autopsy). Read only these files
first, nothing else:
- CONTRIBUTING.md (rules and report layout)
- apps/_template/report/README.md (skeleton to copy)
- apps/ola/report/README.md (example of a finished report)

Target: <APP NAME>. Look for its binary at
apps/<app-name>/artifacts/ first — repo apps keep them there. If it's not
there, get it from <WHERE TO GET IT — path, store page, or device>.
If jadx/apktool are missing, run tools/setup.sh first.

Analyze it with whatever fits (jadx, apktool, ghidra, frida), then write
the report to apps/<app-name>/report/ following the template contract:
the 9-row identity table; What this is / Findings / Layout of this report /
Coverage / Limitations sections; all 13 coverage rows filled or marked
n/a; every claim tagged obs/inf/unk. Add a row to the matching page under
categories/ and run tools/build-index.sh. Never commit binaries or
decompiled source.
```

## Layout

Only the reports are committed. Binaries and decompiled output stay on the
analyst's machine: they're large, easy to regenerate, and not ours to
redistribute.

```
apps/<app-name>/
  artifacts/  the binaries under the knife (apk, ipa, exe, elf...)  (gitignored)
  analysis/   decompiled trees, work dirs                           (gitignored)
  report/     the teardown write-up                                 (tracked)
```
